# Участие в проекте

Баг-репорты, идеи и пул-реквесты приветствуются. Общаться в issues и пул-реквестах можно по-русски и по-английски.

## Сообщить об ошибке или предложить идею

Откройте [issue](https://github.com/SergeyShk/ruMorph/issues/new/choose) по шаблону. Для ошибки нужны словоформы или код, на которых она проявляется, ожидаемый и фактический результат, версии ruMorph, Python и ОС. Для идеи - какую задачу вы решаете и почему текущих возможностей не хватает.

## Окружение разработки

Проект использует [uv](https://docs.astral.sh/uv/) для управления зависимостями, [maturin](https://www.maturin.rs/) для сборки модуля на Rust и [ruff](https://docs.astral.sh/ruff/) для линтинга и форматирования. Требуются Python 3.11 или новее и [Rust](https://www.rust-lang.org/tools/install) 1.88 или новее.

```bash
git clone https://github.com/SergeyShk/ruMorph.git
cd ruMorph

make deps                   # создать окружение, установить все зависимости и собрать модуль на Rust
make dictionary             # собрать словарь из pymorphy3-dicts-ru
uv run pre-commit install   # хуки: линтеры на коммите, тесты на пуше
```

Модуль на Rust собирается при установке пакета в окружение; `uv run` пересобирает его сам, когда меняются файлы `crates/` или `Cargo.toml`. Словарь `python/rumorph/data/ru.dict` в git не хранится: `make dictionary` выгружает словарь pymorphy3-dicts-ru скриптом `scripts/export_pymorphy.py` и собирает его сборщиком `rumorph-build`; `make test` и `make build` делают это сами. Полный список команд - `make help`.

## Проверки

Перед отправкой пул-реквеста должны проходить:

```bash
make lint        # ruff check --fix, ruff format, mypy, cargo fmt, cargo clippy
make test-cov    # pytest с примерами из докстрингов (doctest) и порогом покрытия, cargo test
make docs-build  # mkdocs build --strict, если менялась документация
```

То же самое выполняет CI на Python 3.11-3.14 и 3.14t без GIL (Linux), на Windows и macOS для одной версии Python, а также проверяет сборку на минимальной версии Rust 1.88. Повышая минимальную версию Rust, меняйте ее в `rust-version` в `Cargo.toml`, в задаче `msrv` в `ci.yml` и в документации.

## Что ожидается в пул-реквесте

- **Одна тема - один пул-реквест.** Правки не по теме лучше вынести отдельно.
- **Тесты.** Новый код покрыт тестами: код на Rust - тестами в `crates/` на маленьких словарях, собранных в самом тесте, API для Python - тестами в `tests/` на настоящем словаре, покрытие Python не ниже 90 %. Примеры из докстрингов модуля на Rust выполняются как doctest.
- **Документация.** Документация двуязычная - русская страница `docs/*.md` и английская `docs/*.en.md` рядом, тест `tests/test_docs.py` следит, чтобы у них совпадали разделы, якоря и ссылки. Примеры в докстрингах и документации показывают фактический вывод.
- **Совместимость.** Изменение Python API, разборов и формата словаря - только с пояснением в описании пул-реквеста: оно попадет в заметки релиза. Изменение формата словаря поднимает его версию в `crates/rumorph/src/format.rs`.
- **Стиль.** Код Python форматируется ruff, типы проверяются mypy; код Rust форматируется rustfmt и проверяется clippy без предупреждений (`make format`, `make lint`). Докстринги и комментарии - на русском, имена в коде - на английском. Комментарии в коде не дублируют то, что видно из него самого.
- **Коммиты.** Сообщения на русском в повелительном наклонении: «Добавить …», «Исправить …», «Убрать …».

Описание пул-реквеста отвечает на два вопроса: что сделано и почему. Если пул-реквест закрывает issue, укажите его номер.

## Как устроен репозиторий

- `crates/rumorph/` - ядро анализатора на Rust: формат словаря, сборка (feature `build`) и разбор; публикуется на crates.io.
- `crates/rumorph-dict-ru/` - крейт со словарем для `rumorph` (feature `bundled`): файл словаря в git не хранится, `build.rs` берет `python/rumorph/data/ru.dict`, а без него собирает крейт с пустым словарем.
- `crates/rumorph-build/` - сборка словаря из выгрузки pymorphy3-dicts-ru и перевод тегов OpenCorpora в UD (`ud.rs`).
- `crates/rumorph-py/` - модуль Python `rumorph._rumorph` на PyO3.
- `python/rumorph/` - пакет Python поверх модуля; `data/ru.dict` - собранный словарь.
- `scripts/` - выгрузка словаря pymorphy3-dicts-ru и проверка установленного пакета перед публикацией.
- `tests/` - тесты пакета Python; `tests/test_pymorphy.py` сверяет разборы с pymorphy3 на частых словоформах, `tests/test_docs.py` - два языка документации.
- `docs/` - документация MkDocs (Material), `mkdocs.yml` - навигация и перевод ее на английский.
- `.github/workflows/` - CI (`ci.yml`), публикация (`publish.yml`: словарь собирается один раз и входит в колеса для Linux, macOS и Windows и в исходники), документация (`docs.yml`).

Версия пакета хранится в `pyproject.toml` и в `Cargo.toml` в записи semver (`0.1.0.dev1` - `0.1.0-dev.1`); зависимость `rumorph` от `rumorph-dict-ru` закреплена той же версией (`=0.1.0-dev.1`). Их совпадение проверяет тест. Тег версии запускает `publish.yml`: колеса и исходники собираются один раз, проверяются на всех платформах и публикуются на TestPyPI, а версия без `.devN` затем - на PyPI и крейтами на crates.io. Изменения описываются в заметках GitHub Release, отдельного файла CHANGELOG нет.
