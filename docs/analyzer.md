# Анализатор

``` {.python .signature}
Analyzer(path=None, words=None)
```

Морфологический анализатор: для словоформы находит по словарю OpenCorpora все варианты [разбора](analysis.md) - начальную форму, часть речи и признаки [Universal Dependencies](https://universaldependencies.org/) - и упорядочивает их по вероятности. Словарь загружается при создании первого анализатора: анализаторы с тем же файлом словаря в процессе делят его, поэтому новый анализатор создается мгновенно. Последний загруженный словарь остается в процессе и без анализаторов, поэтому задачи пула процессов и анализатор, созданный на один вызов, не загружают словарь заново.

Исключения:

- `FileNotFoundError` - нет файла словаря;
- `OSError` - файл словаря не читается: нет доступа, путь указывает на каталог;
- `ValueError` - файл не словарь ruMorph или поврежден, или у [своего слова](#words) нет образца в словаре, образец неоднозначен, слово не изменяется по нему или в слове пробел, управляющий или невидимый символ;
- `TypeError` - путь, который не строка и не `PathLike`, или свои слова - не словарь строк.

=== "Код"

    ``` python
    from rumorph import Analyzer

    morph = Analyzer()
    morph.analyze("стали")[0]
    ```

=== "Результат"

    ```
    Analysis(word='стали', lemma='стать', pos='VERB', feats='Aspect=Perf|Mood=Ind|Number=Plur|Tense=Past|VerbForm=Fin|Voice=Act', labels='intr', prob=0.9877829877829878, source='dictionary')
    ```

## Параметры

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `path` | `str` / `PathLike` | `None` | Путь к файлу словаря; по умолчанию - словарь из пакета |
| `words` | `Mapping[str, str \| tuple[str, str]]` | `None` | [Свои слова](#words) и их образцы |

Объект хранит путь к словарю в `path` типа `Path`, только для чтения. Файл словаря отображается в память: процессы с одним файлом делят его память, поэтому каждый следующий процесс с анализатором занимает около 1,2 МБ. Пока анализатор существует, файл нельзя перезаписывать на месте, а заменить новым файлом можно; в Windows открытый файл не заменяется и не удаляется. Последний загруженный словарь остается открытым и после удаления анализаторов - до загрузки словаря из другого файла или выхода из процесса: чтобы освободить файл своего словаря, например перед его удалением в Windows, удалите его анализаторы и разборы и создайте анализатор со словарем пакета: `Analyzer()`. Словарь - доверенные данные, как код: загрузка отвергает поврежденный файл, но не любой специально подделанный, поэтому словари из ненадежных источников загружать не стоит.

## Свои слова { #words }

Слово, которого нет в словаре, можно добавить по образцу - словарному слову, которое изменяется так же: «зумер» - как «геймер», «кринж» - как «пляж». Слово и образец пишутся в одной форме, обычно в начальной; знаки ударения, мягкие переносы и латинские буквы-двойники в них приводятся, как в запросе. Свое слово получает все формы образца со своей основой и дальше ведет себя как словарное: `source` - `"dictionary"`, `is_known` его находит, работают `forms`, `inflect` и `agree`. Если у образца лексемы разных частей речи («печь» - существительное и глагол), образец - пара с частью речи UD: `{"зечь": ("печь", "VERB")}`; иначе анализатор не создается. Образцом может быть и свое слово, стоящее раньше: `{"зумер": "геймер", "бумер": "зумер"}`. Свои слова есть только у этого анализатора, а pickle сохраняет их вместе с ним.

Свои слова хранятся в копии словаря, около 3,5 КБ на слово (35 МБ на 10 тыс. слов). Отображенный в память словарь процессы делят, а копию каждый процесс собирает сам. Последняя собранная копия остается в памяти и после удаления анализаторов, пока не собрана другая или не загружен другой словарь: задачи пула процессов не собирают ее заново.

=== "Код"

    ``` python
    morph = Analyzer(words={"зумер": "геймер", "кринж": "пляж"})
    zoomer = morph.analyze("зумерами")[0]
    zoomer.lemma, zoomer.inflect(Case="Dat", Number="Sing"), morph.lemmatize(["кринжем"])
    ```

=== "Результат"

    ```
    ('зумер', 'зумеру', ['кринж'])
    ```

## Методы

### Разборы словоформы { #analyze }

`analyze` · `list[Analysis]`
{ .metric-meta }

``` {.python .signature}
analyze(word)
```

Разборы словоформы по убыванию вероятности; сумма вероятностей равна 1. Регистр не важен для поиска, а буква «е» может обозначать «ё»: `analyze("ЕЖ")` возвращает разборы словоформы «ёж». Вероятности регистр учитывают: у строчного слова имена собственные идут последними («шаров» - «шар»), а у слова с заглавной буквы их доля выше («Шаров» - фамилия). Токен, которого нет в словаре, - число, знак, слово латиницей, сокращение - разбирается [по правилам](analysis.md#rules), а разборы незнакомого слова кириллицей [угадываются](analysis.md#guess) по окончанию и по частям. Токен без пробелов и невидимых символов получает хотя бы один разбор: если ничего не подошло - `X` без признаков.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `word` | `str` | - | Словоформа |

Исключения:

- `TypeError` - слово, которое не строка.

=== "Код"

    ``` python
    [(a.lemma, a.pos, a.feats.get("Case"), round(a.prob, 3)) for a in morph.analyze("стали")]
    [(a.lemma, a.source) for a in morph.analyze("чатботу")][:2]
    ```

=== "Результат"

    ```
    [('стать', 'VERB', None, 0.988),
     ('сталь', 'NOUN', 'Gen', 0.005),
     ('сталь', 'NOUN', 'Nom', 0.003),
     ('сталь', 'NOUN', 'Dat', 0.001),
     ('сталь', 'NOUN', 'Loc', 0.001),
     ('сталь', 'NOUN', 'Acc', 0.001)]
    [('чатбот', 'guess'), ('чатбота', 'guess')]
    ```

### Разборы списка словоформ { #analyze_many }

`analyze_many` · `list[list[Analysis]]`
{ .metric-meta }

``` {.python .signature}
analyze_many(words)
```

Разборы каждой словоформы, как у [`analyze`](#analyze); на списке метод быстрее, чем `analyze` в цикле.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `words` | `Iterable[str]` | - | Словоформы: список, кортеж, генератор |

Исключения:

- `TypeError` - строка вместо набора слов, слово, которое не строка.

=== "Код"

    ``` python
    [len(analyses) for analyses in morph.analyze_many(["мама", "мыла", "раму"])]
    ```

=== "Результат"

    ```
    [1, 4, 2]
    ```

### Разбор предложения { #analyze_sentence }

`analyze_sentence` · `list[list[Analysis]]`
{ .metric-meta }

``` {.python .signature}
analyze_sentence(words)
```

Разборы слов предложения с учетом контекста: те же разборы, что у [`analyze`](#analyze), упорядочивает контекстная модель - первым идет разбор, который она выбрала по соседним словам, а `prob` - ее оценка в этом предложении. Без контекста «книги» - в родительном падеже (так чаще), в «Я читаю книги» модель выбирает винительный, а «стали» в «Мост сделан из стали» - существительное «сталь», а не глагол «стать». С контекстом часть речи, лемма и признаки первого разбора верны у 82-94 % слов против 71-82 % без него ([Сравнение](performance.md)). Слова - токены одного предложения по порядку: ruMorph не делит текст на предложения и токены. Слово без соседей разбирается, как у `analyze`: без контекста модель выбирает хуже частот словаря. Предложение длиннее 256 слов модель разбирает частями по 256, чтобы ее память не росла с длиной входа. Модель обучена на трибанках [UD_Russian-Taiga](https://github.com/UniversalDependencies/UD_Russian-Taiga), [UD_Russian-GSD](https://github.com/UniversalDependencies/UD_Russian-GSD) и корпусе [OpenCorpora](https://opencorpora.org) и входит в словарь пакета.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `words` | `Iterable[str]` | - | Токены предложения: список, кортеж, генератор |

Исключения:

- `TypeError` - строка вместо набора слов, слово, которое не строка;
- `ValueError` - в словаре нет контекстной модели (словарь, собранный без нее).

=== "Код"

    ``` python
    words = ["Я", "читаю", "книги"]
    print([analyses[0].feats.get("Case") for analyses in morph.analyze_many(words)])
    print([analyses[0].feats.get("Case") for analyses in morph.analyze_sentence(words)])
    print(morph.analyze_sentence(["Мост", "сделан", "из", "стали"])[3][0].lemma)
    ```

=== "Результат"

    ```
    ['Nom', None, 'Gen']
    ['Nom', None, 'Acc']
    сталь
    ```

### Лемматизация { #lemmatize }

`lemmatize` · `list[str]`
{ .metric-meta }

``` {.python .signature}
lemmatize(words)
```

Леммы самых вероятных разборов словоформ; токен без разборов возвращается в нижнем регистре.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `words` | `Iterable[str]` | - | Словоформы: список, кортеж, генератор |

Исключения:

- `TypeError` - строка вместо набора слов, слово, которое не строка.

=== "Код"

    ``` python
    morph.lemmatize("Мы стали друзьями в ковиде".split())
    ```

=== "Результат"

    ```
    ['мы', 'стать', 'друг', 'в', 'ковид']
    ```

### Словоформа в словаре { #is_known }

`is_known` · `bool`
{ .metric-meta }

``` {.python .signature}
is_known(word)
```

Есть ли словоформа в словаре; регистр и «е» вместо «ё», как у `analyze`, не важны. Слова, разобранные по правилам или угаданные, в словаре не числятся.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `word` | `str` | - | Словоформа |

Исключения:

- `TypeError` - слово, которое не строка.

=== "Код"

    ``` python
    morph.is_known("Ежи"), morph.is_known("вайб")
    ```

=== "Результат"

    ```
    (True, False)
    ```

</div>

## Словарь { #dictionary }

Словарь пакета собран из словаря [OpenCorpora](https://opencorpora.org): около 3,1 млн словоформ. Вероятности разборов взяты из корпуса OpenCorpora и уточнены по разметке трибанков Universal Dependencies [UD_Russian-Taiga](https://github.com/UniversalDependencies/UD_Russian-Taiga) и [UD_Russian-GSD](https://github.com/UniversalDependencies/UD_Russian-GSD): так «ничего» чаще местоимение, чем наречие. У словоформ, которых нет ни в одном корпусе, разборы равновероятны. Словарь распространяется по лицензии [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).

## Потоки и процессы { #parallel }

Один анализатор можно использовать из нескольких потоков: `analyze_many` и `lemmatize` отпускают GIL и разбирают списки параллельно, а в Python 3.14t без GIL параллельно работают и `analyze`, `is_known`, `inflect` и `agree`. Общий анализатор не медленнее отдельного на каждый поток, поэтому заводить анализатор на поток не нужно. Без GIL потоки упираются в удаление объектов разборов: `forms` в потоках почти не ускоряется, а `analyze_many` на длинных списках - слабо, поэтому такие списки лучше разбирать кусками по тысяче-другой слов. Анализатор и разборы сохраняются через pickle, поэтому работают с `multiprocessing` и joblib: процессы делят отображенный в память словарь, сколько бы разборов они ни получили (копию со [своими словами](#words) каждый процесс собирает сам). pickle хранит путь к словарю: при распаковке берется анализатор с тем же путем, разборы которого есть в потоке, иначе словарь загружается по пути, а если файла уже нет - берется словарь, загруженный из него в процессе. Разбор, сохраненный со словарем другой версии, находится по написанию, лемме и тегу; если такого разбора в словаре нет, он восстанавливается как сохранен, но без других форм, а если в словаре нет и его тега - берется разбор слова с теми же леммой и частью речи, у которого совпало больше всего признаков (род «Нидерландов», будущее время «будет» из 0.3.0). Подынтерпретаторы Python 3.14 (`InterpreterPoolExecutor`) не поддерживаются: используйте потоки или процессы. Передача разборов между процессами дороже самого разбора, поэтому в процессах лучше получать леммы и поля разборов, а разборы - в потоках.

=== "Код"

    ``` python
    from concurrent.futures import ThreadPoolExecutor

    texts = [["мама", "мыла", "раму"], ["кошки", "ловят", "мышей"]]
    with ThreadPoolExecutor(2) as pool:
        lemmas = list(pool.map(morph.lemmatize, texts))
    lemmas
    ```

=== "Результат"

    ```
    [['мама', 'мыть', 'рама'], ['кошка', 'ловить', 'мышь']]
    ```
