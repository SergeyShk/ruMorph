# Анализатор

``` {.python .signature}
Analyzer(path=None)
```

Морфологический анализатор: для словоформы находит по словарю OpenCorpora все варианты [разбора](analysis.md) - начальную форму, часть речи и признаки [Universal Dependencies](https://universaldependencies.org/) - и упорядочивает их по вероятности. Словарь загружается при создании первого анализатора: анализаторы с тем же файлом словаря в процессе делят его, поэтому новый анализатор создается мгновенно. Последний загруженный словарь остается в процессе и без анализаторов, поэтому задачи пула процессов и анализатор, созданный на один вызов, не загружают словарь заново.

Исключения:

- `FileNotFoundError` - нет файла словаря;
- `OSError` - файл словаря не читается: нет доступа, путь указывает на каталог;
- `ValueError` - файл не словарь ruMorph или поврежден;
- `TypeError` - путь, который не строка и не `PathLike`.

=== "Код"

    ``` python
    from rumorph import Analyzer

    morph = Analyzer()
    morph.analyze("стали")[0]
    ```

=== "Результат"

    ```
    Analysis(word='стали', lemma='стать', pos='VERB', feats='Aspect=Perf|Mood=Ind|Number=Plur|Tense=Past|VerbForm=Fin|Voice=Mid', labels='intr', prob=0.9753459013836056, source='dictionary')
    ```

## Параметры

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `path` | `str` / `PathLike` | `None` | Путь к файлу словаря; по умолчанию - словарь из пакета |

Объект хранит путь к словарю в `path` типа `Path`, только для чтения. Файл словаря отображается в память: процессы с одним файлом делят его память, поэтому каждый следующий процесс с анализатором занимает около 1,4 МБ. Пока анализатор существует, файл нельзя перезаписывать на месте, а заменить новым файлом можно; в Windows открытый файл не заменяется и не удаляется. Последний загруженный словарь остается открытым и после удаления анализаторов - до загрузки словаря из другого файла или выхода из процесса: чтобы освободить файл своего словаря, например перед его удалением в Windows, удалите его анализаторы и разборы и создайте анализатор со словарем пакета: `Analyzer()`. Словарь - доверенные данные, как код: загрузка отвергает поврежденный файл, но не любой специально подделанный, поэтому словари из ненадежных источников загружать не стоит.

## Методы

<div class="metric-card" markdown>

### Разборы словоформы { #analyze }

`analyze` · `list[Analysis]`
{ .metric-meta }

``` {.python .signature}
analyze(word)
```

Разборы словоформы по убыванию вероятности; сумма вероятностей равна 1. Регистр не важен для поиска, а буква «е» может обозначать «ё»: `analyze("ЕЖ")` возвращает разборы словоформы «ёж». Вероятности регистр учитывают: у строчного слова имена собственные идут последними («шаров» - «шар»), а у слова с заглавной буквы их доля выше («Шаров» - фамилия). Токен, которого нет в словаре, - число, знак, слово латиницей, сокращение - разбирается [по правилам](analysis.md#rules), а разборы незнакомого слова кириллицей [угадываются](analysis.md#guess) по окончанию и по частям. Токен без пробелов и невидимых символов получает хотя бы один разбор: если ничего не подошло - `X` без признаков.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `word` | `str` | - | Словоформа |

Исключения:

- `TypeError` - слово, которое не строка.

=== "Код"

    ``` python
    [(a.lemma, a.pos, a.feats.get("Case"), round(a.prob, 3)) for a in morph.analyze("стали")]
    [(a.lemma, a.source) for a in morph.analyze("чатботу")][:2]
    ```

=== "Результат"

    ```
    [('стать', 'VERB', None, 0.975),
     ('сталь', 'NOUN', 'Gen', 0.011),
     ('сталь', 'NOUN', 'Nom', 0.005),
     ('сталь', 'NOUN', 'Dat', 0.003),
     ('сталь', 'NOUN', 'Loc', 0.003),
     ('сталь', 'NOUN', 'Acc', 0.003)]
    [('чатбот', 'guess'), ('чатбота', 'guess')]
    ```

### Разборы списка словоформ { #analyze_many }

`analyze_many` · `list[list[Analysis]]`
{ .metric-meta }

``` {.python .signature}
analyze_many(words)
```

Разборы каждой словоформы, как у [`analyze`](#analyze); на списке метод быстрее, чем `analyze` в цикле.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `words` | `Iterable[str]` | - | Словоформы: список, кортеж, генератор |

Исключения:

- `TypeError` - строка вместо набора слов, слово, которое не строка.

=== "Код"

    ``` python
    [len(analyses) for analyses in morph.analyze_many(["мама", "мыла", "раму"])]
    ```

=== "Результат"

    ```
    [1, 4, 2]
    ```

### Лемматизация { #lemmatize }

`lemmatize` · `list[str]`
{ .metric-meta }

``` {.python .signature}
lemmatize(words)
```

Леммы самых вероятных разборов словоформ; токен без разборов возвращается в нижнем регистре.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `words` | `Iterable[str]` | - | Словоформы: список, кортеж, генератор |

Исключения:

- `TypeError` - строка вместо набора слов, слово, которое не строка.

=== "Код"

    ``` python
    morph.lemmatize("Мы стали друзьями в ковиде".split())
    ```

=== "Результат"

    ```
    ['мы', 'стать', 'друг', 'в', 'ковид']
    ```

### Словоформа в словаре { #is_known }

`is_known` · `bool`
{ .metric-meta }

``` {.python .signature}
is_known(word)
```

Есть ли словоформа в словаре; регистр и «е» вместо «ё», как у `analyze`, не важны. Слова, разобранные по правилам или угаданные, в словаре не числятся.

| Параметр | Тип | По умолчанию | Описание |
| :------- | :-- | :----------- | :------- |
| `word` | `str` | - | Словоформа |

Исключения:

- `TypeError` - слово, которое не строка.

=== "Код"

    ``` python
    morph.is_known("Ежи"), morph.is_known("вайб")
    ```

=== "Результат"

    ```
    (True, False)
    ```

</div>

## Словарь { #dictionary }

Словарь пакета собран из словаря [OpenCorpora](https://opencorpora.org): около 3,1 млн словоформ. Вероятности разборов взяты из корпуса OpenCorpora: у слова, написанного через «е» вместо «ё», - частоты написания с «ё», у словоформ, которых в корпусе нет, разборы равновероятны. Словарь распространяется по лицензии [CC BY-SA 3.0](https://creativecommons.org/licenses/by-sa/3.0/).

## Потоки и процессы { #parallel }

Один анализатор можно использовать из нескольких потоков: `analyze_many` и `lemmatize` отпускают GIL и разбирают списки параллельно, а в Python 3.14t без GIL параллельно работают и `analyze`, `is_known`, `inflect` и `agree`. Общий анализатор не медленнее отдельного на каждый поток, поэтому заводить анализатор на поток не нужно. Без GIL потоки упираются в удаление объектов разборов: `forms` в потоках почти не ускоряется, а `analyze_many` на длинных списках - слабо, поэтому такие списки лучше разбирать кусками по тысяче-другой слов. Анализатор и разборы сохраняются через pickle, поэтому работают с `multiprocessing` и joblib: процессы делят отображенный в память словарь, сколько бы разборов они ни получили. pickle хранит путь к словарю: при распаковке берется анализатор с тем же путем, разборы которого есть в потоке, иначе словарь загружается по пути, а если файла уже нет - берется словарь, загруженный из него в процессе. Подынтерпретаторы Python 3.14 (`InterpreterPoolExecutor`) не поддерживаются: используйте потоки или процессы. Передача разборов между процессами дороже самого разбора, поэтому в процессах лучше получать леммы и поля разборов, а разборы - в потоках.

=== "Код"

    ``` python
    from concurrent.futures import ThreadPoolExecutor

    texts = [["мама", "мыла", "раму"], ["кошки", "ловят", "мышей"]]
    with ThreadPoolExecutor(2) as pool:
        lemmas = list(pool.map(morph.lemmatize, texts))
    lemmas
    ```

=== "Результат"

    ```
    [['мама', 'мыло', 'рама'], ['кошка', 'ловить', 'мышь']]
    ```
